# Flight Recorder — Control4 capability and compatibility matrix

Audit date: 2026-10-22. Ranking rule of this repo: hardware measurements >
shipped drivers > official docs > nothing. Evidence classes: **MEASURED** (on
our controllers), **VERIFIED_BY_EXAMPLE** (a plaintext shipped driver in
`~/Documents/Control4/Drivers` does it; counts are from a census over the 123
`.c4z`/`.c4i` files with a readable `driver.lua`), **VERIFIED_BY_DOCS**
(`docs/control4-capabilities.md`, `docs/AGENT_TELEMETRY.md`, the vendored
`drivers-common-public` library), **UNCONFIRMED** (may not be a design
dependency), **PROBE** (tried and reported, never depended on).

Minimum OS: every driver in this repo declares `minimum_os_version` 3.3.1 or
3.3.2; the bench controllers run OS 4.2. Nothing below needs more than 3.3.x
except where noted. "Controller validation" is what the owner must still see
on the bench before the row counts as hardware-verified.

## Rules the design follows

1. **Subscriptions first.** Variable listeners for every selected source; no
   periodic re-read of selected variables except the one bounded read that
   produces the initial observation and the on-demand snapshot read.
2. **Bounded polling only where justified.** The only poll is the Agent's
   existing 5-minute device-state poll (unchanged). Discovery runs on request
   and is cached.
3. **Never the whole project continuously.** `max_sources` caps the listener
   set; `discover` reads one device's variables at a time on request.
4. **Nothing UNCONFIRMED is a dependency.** `GetDeviceEvents`, blink APIs,
   Composer tabs, file-sandbox durability are not relied on.
